Cluster example

Run this example with node cluster.js in your Achieve install directory instead of start.js.

Then, in a separate console, try: 

autocannon -c 100 -d 30 -p 1 http://localhost:8989/cluster/servlets/hello.jss

You can install Autocannon with: npm install -g autocannon

Experiment with Autocannon

Try changing the number of concurrent connections (-c) and the pipelining factor (-p) to see how they affect throughput and latency. 

autocannon -c 200 -d 30 -p 1 http://localhost:8989/cluster/servlets/hello.jss
autocannon -c 400 -d 30 -p 1 http://localhost:8989/cluster/servlets/hello.jss
autocannon -c 100 -d 30 -p 10 http://localhost:8989/cluster/servlets/hello.jss

-c sets the number of concurrent connections, -d sets the test duration in seconds, and -p sets the HTTP/1.1 pipelining factor.

Watch both requests per second and latency as you change the settings. Higher concurrency or pipelining can increase throughput, but may also increase latency.

Experiment with Cluster

By default, cluster.js uses os.availableParallelism() to choose the number of workers. The number is displayed when the cluster starts.

To experiment with different numbers of worker processes, replace: 

const workers = os.availableParallelism();

with, for example:

const workers = 1;

Try 1, 2, 4, or more workers and compare the Autocannon results. Be aware of the number of cores of your CPU. Restart the cluster after changing the number of workers.

Benchmark results depend heavily on hardware and test settings. When reporting results, include the Autocannon options and number of workers you used.

See the Autocannon documentation for additional options.
