Technical Specifications

Focused specifications explain what a protocol feature requires, how Achieve and its qualified Node.js runtime implement it, how the behavior is verified, and which limitations remain. They are the primary entry point for readers interested in Achieve's HTTP behavior.

HTTP Standards

RFC 9110 — HTTP Semantics

  • Achieve RFC 9110 §8.8.3 ETag — metadata-based strong validators and representation distinctions.
  • Achieve RFC 9110 §13 Conditional Requests — validator preconditions, precedence, and response behavior.
  • HTTP Methods and Responses — built-in and registered methods, completion, content rules, and status-specific behavior.
  • Range Requests and Partial Responses — byte ranges, If-Range, 206 and 416 responses, and single-range limits.
  • Content Negotiation — identity, gzip, and deflate selection, content coding, quality values, and Vary.

RFC 9111 — HTTP Caching

  • HTTP Caching — origin-server metadata, validators, revalidation, and the boundary with external caches.

RFC 9112 — HTTP/1.1

  • HTTP/1.1 Message Framing — message length, transfer coding, chunking, trailers, connections, and the Node parser boundary.
  • HTTP/1.1 Connections — request completion, reuse, pipelining, explicit close behavior, and TLS closure.
  • Request Targets and Authority — HTTP/1.1 target forms, Host, HTTP/2 authority, validation, and routing handoff.

RFC 9113 — HTTP/2

  • HTTP/2 Stream Errors and Connection Errors — required error scope and codes, Node/nghttp2 behavior, and qualified-runtime limitations.
  • HTTP/2 Stream States — lifecycle, identifiers, concurrency limits, permitted frames, and known error-scope limitations.
  • HTTP/2 Frames — binary framing, limits, SETTINGS, PING, field-block sequencing, and the runtime boundary.
  • HTTP/2 Header Compression — HPACK state, contiguous field blocks, decoding failures, and compression-context verification.
  • HTTP/2 Flow Control — connection and stream windows, DATA accounting, WINDOW_UPDATE, SETTINGS, and runtime limitations.
  • HTTP/2 Request Fields — pseudo-header ordering and presence, lowercase names, prohibited fields, and malformed-request handling.

Achieve Features

Implementation articles describe stable Achieve facilities without forcing them into a standards-audit structure.

  • Logging in Achieve — startup reporting, development diagnostics, persistent server logs, access logs, and servlet errors.
  • Error Handling and Response Recovery — managed failures, incomplete responses, diagnostics, and application-owned work.
  • Application-Space Routing — required application root, automatic routes, exact and subtree mappings, precedence, and containment.
  • JavaScript Servlet Lifecycle — loading, session state, synchronous and asynchronous results, completion ownership, errors, and caching.
  • Static Resources — application-space lookup, media types, descriptor-based delivery, containment, and response behavior.
  • Static Compression — asynchronous artifact generation, representation selection, freshness, reuse, and protected cache storage.
  • Request Input — query parameters, buffered POST parsing, size limits, streaming, and application responsibilities.
