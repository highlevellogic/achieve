V3-9110-008 — RFC 9110 §5.3

Conformant Normative level: MUST NOT

Requirement
A sender must not generate duplicate field lines unless the field permits list recombination.
Conditions
Apply only under the conditions and exceptions stated in the cited section and summarized in the requirement.
Applicable role
sender
Responsible layer
Achieve for core-generated fields; servlet application for application-authored fields; Node serializes
Implementation evidence
Core response paths use setHeader/writeHead objects, which replace or uniquely name fields; the only appendHeader use is Vary: Origin, whose definition permits list recombination. Achieve does not synthesize duplicate non-list field lines.
Test evidence
Batch B wire captures found no duplicate non-list core fields on representative HTTP/1.1 and h2c static, range, conditional, and error responses. A negative-control servlet deliberately setting an array for X-Non-List produced duplicate HTTP/1.1 lines, confirming that Node does not enforce application semantics.
Assessment rationale
Achieve-generated output satisfies the sender obligation. The negative control is application-authored misuse through the general Node response API, not an Achieve-generated protocol defect.
Open question
Servlet authors remain responsible for field definitions when deliberately supplying multiple values.

Conformant Normative level: MAY

Requirement
A recipient MAY combine repeated field lines with the same name only without changing message semantics, preserving their order and using comma plus optional whitespace.
Conditions

Applicable role
recipient
Responsible layer
Node.js/shared
Implementation evidence
Node parses request fields before achieveApp at achieve.js:1407-1441 and exposes normalized and raw field views to Achieve.
Test evidence
Batch C raw HTTP/1.1 probes on Node.js 22.15.0 observed ordered comma-SP combination of repeated Accept, semicolon-SP combination of Cookie, retention of the first Authorization value without combination, rejection of duplicate Content-Length with 400, and preservation of all original lines in rawHeaders; standalone Node produced identical results.
Assessment rationale
The exercised list, special-case, non-list, and invalid framing controls show that the combinations Node performs preserve the applicable field semantics and order. Achieve does not recombine the lines independently.
Open question
Bounded to Node.js 22.15.0 and the field classes exercised; newly defined field semantics remain dependent on Node parser support.
